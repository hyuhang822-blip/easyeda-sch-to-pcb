# 坑清单总表（立创EDA专业版 · 原理图→PCB）

> **遇到怪现象先来这查。** 每条 = 「症状 → 根因 → 对策」。全部来自实盘踩坑（括号里的数字是实测样例，仅作量级参考）。
> 标 ★ 的是"栽过大跟头 / 极隐蔽"的。

## A. 连接与环境

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **A1** | `curl /health` 返 **502 Bad Gateway**，但 bridge 明明活着 | 沙箱/CI 注入了 `http_proxy`，把 `127.0.0.1` 也代理走了 | 跑任何脚本前 `export no_proxy="127.0.0.1,localhost" NO_PROXY=…` |
| A2 | 刚 `/health` 成功，下一条命令就 `Connection refused` | `nohup … &` 起的 bridge 随该次调用结束被回收 | 用**受管后台任务**常驻 |
| A3 | `edaConnected:false` 一直不变 | 扩展自动重试约 5 次即停；bridge 重启 / EDA 先启动都会错过 | 先 `/health` 长轮询 ≥100s；仍不通请用户点 **API Gateway → 重新连接** |

| A6 | `ModuleNotFoundError: numpy` / 绘图库缺失 | 用了解释器但没装依赖 | 固定用一个装了依赖的解释器 |

## B. ★★★ 存储与持久化（"API 说成功，重开就回退"）

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **B1** | `sch_PrimitiveText` 的 `delete / modify / setState_* + done()` **全返 true、会话内生效，关页签重开全回退** | 文字类图元**不落盘**（`save()` 返 true 也没用） | **改/删文字只能走页源文本手术**（`getDocumentSource` → 按行改 → `setDocumentSource` → `save`） |
| **B2** | `Wire.modify(id,{line})` 返真但**没改**，还让画布**凭空少线**（实测 154→127） | 该 modify 分支无效 | 导线改坐标**只能 delete + create**（分批） |
| B3 | `obj.modify({...})` 报 `X.modify is not a function` | `modify` 是**类上的静态方法** | `await eda.sch_PrimitiveXxx.modify(id, props)` |
| **B4** | 删完复核**一条没少** | `PrimitiveText.delete(ids)` 对 TEXT **返回真但不落盘**（曾一次删 132 个 id 全"成功"而无一减少） | 删除后**独立复核残留**（读回全部图元按内容/区域再数一遍） |
| **B5** | 删了 A 处的图元，B 处也少了一份 | 同内容的图元**存在两份**：早期 y 符号写错留下的**镜像副本**（在页面另一侧之外） | **按内容删所有副本**，别只删"范围内的那一份" |
| **B6** | 存盘后关页签，只存了一部分（实测 81/163） | **`save()` 是异步的** | 存盘后**等 4~6 秒**再关页签；`save()` 返 `false` 要重试 |
| B7 | "在 JS 里 split/join 改源再写回"没效果 | 该写法**不落盘** | **在宿主（Python）侧拼好整份字符串**再发过去 |
| B8 | `lib_Footprint.updateDocumentSource` 返 true 但几何全丢 | 它存的是**客户端自带的空模板**骨架 | 写封装几何走"**打开成文档 + PCB 图元 API**"；且必须**取出文件复读验证**，别信 `true` |
| B9 | "改前备份"被"导出快照"覆盖 | 两个动作共用了文件名 | **备份文件名带动作名**（`*_before` / `*_snapshot`） |
| B10 | 直接改源想新增记录但不生效 | `setDocumentSource` **只能改、不能加记录** | 新建图元用 `create`；只有"改已有记录"才用源手术 |

## C. 坐标 / 单位 / 符号

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **C1** | create 报成功、条数也对，**但整块内容出现在页面另一侧**（镜像） | `create` 传入的 y 符号错了：**页源 y = −(传入 y)** | 页源/PDF 的 y 是**正值（向下）**、API/读回是**负值** ⇒ **一律传负 y**；改完**逐条比对坐标** |
| C2 | `createPolygon([x,y,x,y,…])`（纯数字）**返回 undefined 且不抛异常** | 多边形构造**只认带 `'L'` 标记**的源数组 | 写 `[x,y,'L',x,y,'L',…]` |
| C3 | 板框 bbox 算出来长宽转置 / 整条错位 | 读回的 polygon 是**裸数字与 `'L'` 混排**（长度可能是奇数） | **先滤出所有 number 再两两配对**，别按 `[i] / [i+1]` 跨步取 |
| C4 | 封装几何整块偏离中心 | 局部坐标转过来**又叠加了一次器件 `at` 偏移** | 局部坐标只乘 `39.3701`，**不再加偏移** |
| C5 | 板子上下镜像 | KiCad **+y 朝下**、立创 **+y 朝上** | 落板统一 `y_lc = (y_max − y_k) × 39.3701`；封装局部只翻一次 |
| C6 | 文字位置总差一点 | 从 PDF 抄来的 bbox 是**行盒**不是墨迹 | 对齐按**基准图上的墨迹**量（例：`x ≈ 墨迹左端 − 2.5`、`y = 墨迹垂直中心`，左右对齐模式） |
| C7 | 对齐判读混乱 | `getState_AlignMode()` 读值**不是**源里 `align` 字符串的刻度 | **只看源里的 `align` 字符串** |
| C8 | 折返/平移后出现自交折线、净空全算错 | 同一条走线的点序可能是**降序** | **先归一化成升序**，折完再翻回来 |
| C9 | 从光栅图量坐标总对不上 | 光栅只能到 ±1~2 单位，且被文字/粗线污染 | 坐标优先取**原始 PDF 矢量**；粗线用"行带高"判别分离 |
| C10 | 从 PDF 取同一图元/文字取到 2~3 份 | PDF **多内容流**重复；折线还成对出现**退化零长段** | 按 `(内容,x,y)` / bbox **去重**；先**滤掉零长段** |

## D. 批量写入

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **D1** | `Request … timed out after 30000ms` | **单次 bridge 调用 30s 上限** | **分批**（wire/poly/text 每批 **15 条** ≈3s）；慢接口"发射不等待 + 轮询" |
| **D2** | 板上条数 = 期望 + 一整块（CHUNK） | 客户端超时抛错但**服务端已执行完**，重试又写一遍 | 批量写**幂等**（写前读回已有 key 做差集）+ **写后去重兜底** |
| D3 | 重跑把焊盘/图元**叠加翻倍** | 图元 `create` **不去重** | 写前先读回，已存在就只复核 |
| D4 | 一次调用里塞太多循环就超时 | 同上 | 矩阵/批量扫描拆成多次调用 |
| D5 | 大文件 base64 卡死主线程 | 逐字符 `s += String.fromCharCode(...)` | 用 `String.fromCharCode.apply(null, u8.subarray(i,i+8192))` **8KB 分块** |
| D6 | 长流程中途崩，前面落的全白干 | 扩展重连丢未保存编辑 | 关键步骤之间主动 `save()`；子命令**幂等可续跑** |
| **D7** | 批量落图"看起来都成功了"，但**某类图元实际一条没进** | 分批封装里的异常被**吞掉**（只印一行），而外层只看"没抛错" | ★ **每批都要回传并打印"实际创建条数"**（如 `return {ok:true, made:n}`），别只看有没有抛错 |

## E. 页签与"当前文档"

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **E1** | 批量建到某个数（量级约 38 个）后连续 `openInEditor 未能成为当前文档` | **库文档也攒页签**，额度满（量级：Start Page + 8） | **建完一个就关**：`closeDocument(fpUuid)`；每 10 个 + 开跑前清一遍；**只关库文档那一类，绝不碰原理图页/PCB** |
| E2 | 关完页签后建页抛错、`getCurrentSchematicInfo()` 返 `{}` | **把一个原理图页签都不剩了** | 腾槽时保底留 `≥2` |
| E3 | `activateDocument` 恒 `false`、完全落不了图 | 目标页**没有页签**（额度满/新页没拿到签） | 先关一个腾槽；或 `openDocument(页uuid)` 把它开成页签 |
| E4 | `openDocument` "失败" | 它**很慢**（几秒~90s）且 promise 不及时 resolve | **发射不等待 + 长轮询 ≤90~120s**（短轮询会误判） |
| **E5** | 图元落进了**上一个文档** | 只 `sleep(3)` 就开写 | 写前**轮询到"当前文档 == 目标"** 才继续；超时即中止 |
| E6 | `createSchematicPage / deleteSchematicPage` 挂 30s | API 本身如此，但**操作已生效** | 发射不等待 + **轮询页表确认** |
| E7 | 用**多余参数**建的页**半残**（激活不了、删不掉） | 参数给多了 | 只给必需参数；残页只能界面手删 |
| E8 | 读 `getAll()` 抛 `Cannot read properties of undefined` | **读错文档**（当前文档不是预期那个） | 先确认当前文档；这不代表"板坏了" |
| E9 | `getAll()` 出现坐标异常/超出图框的图元 | 跨文档脏读 | 对账时把这类单独报数，不计失败 |

## F. 库与器件

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **F1** | `lib_*.create` **静默返回 undefined** | 库 uuid 传了 `'project'` | 必须传**"名字即 uuid"的工程库名**；系统库用 `getSystemLibraryUuid()` |
| F2 | `lib_*search` 单次 9–30s，某些关键词直接超时 | 非空 key 是**模糊匹配**且极慢 | **盘点用空 key**（约 0.1s 返回全库）；删除用**精确名匹配** |
| F3 | 误删了无关库项 | 拿 search 结果直接删 | `filter(x => x.name === NAME)` 后再删 |
| F4 | `lib_Symbol / Device.search` 只返回 1 条 | 它们的签名比 `lib_Footprint.search` **多一个 `symbolType` 参数**，照抄导致参数错位 | **查目录前先对签名** |
| F5 | `lib_Symbol.search` 滤不出自己建的东西 | 它会**忽略传入的 libraryUuid**（返回全部库，条目里字段还常为空） | 改成**按精确名匹配** |
| F6 | 落件成功但读不到焊盘（`[]`） | 该封装是**空壳**（中途失败留下的空文档） | 权威判据是**逐个读封装源数焊盘**，不是"名字清单" |
| F7 | `pcb_PrimitiveComponent.create` 的 FOOTPRINT 分支恒抛 TypeError | 该分支坏了（连系统库封装也一样） | 只能走 **DEVICE 分支（`libraryType:'3'`）** |
| F8 | 同一个 `(库, 符号uuid)` 落件第二次挂 30s | 只能落一次 | **每实例唯一 symbol/device uuid** |
| F9 | 器件项里带 `footprint` 关联 ⇒ 落件挂 30s | 客户端要物化封装（某些模式下不可用的库级写） | 原理图阶段**不带 footprint** |
| F10 | 按名字找 PCB 永远找不着，于是每次新建一个空板 | `dmt_Pcb.modifyPcbName(uuid, name)` **返 false 不生效** | **建好立刻把 uuid 落盘**，之后一律按 uuid 走 |

## G. ★ PCB 图元："文档里有、运行时坏"清单

| API | 状态 | 替代 |
|---|---|---|
| `pcb_PrimitiveLine.create` | ❌ **整个不可用**（9 种参数变体全抛；封装/PCB 文档都坏） | **`pcb_PrimitivePolyline.create(net, layer, poly, w)`**（画板框也用它） |
| 封装域 `pcb_PrimitiveString.create` | ❌ 抛"无法创建文本图元" | 位号改在落件后 `Component.modify({designator})` |
| 焊盘 `['POLYGON',…]` / `['NGON',…]` | ❌ 多条路径全灭 | **退化为外接矩形 `['RECT', w, h, 0]`**（面积偏差通常极小） |
| `['ELLIPSE', w, h]` 非正圆 | ❌ 回读把 h 归成 w | 只支持**正圆** |
| `pcb_PrimitivePour.create` | ❌ 5 种签名全抛 | Polyline → `convertToPour()`（但它**在 Gerber 里没铜**，见 H） |
| `pcb_PrimitiveFill.create` | ❌ 三种参数全抛 | Polyline → `convertToFill()` ✅ |
| `pcb_PrimitiveRegion.create` / `pcb_PrimitivePoured.create` | ❌（后者是空壳） | — |
| 原理图侧 `Junction / Dot / NetPoint` | ❌ 运行时不存在 | 渲染期自动画 |
| 原理图 `getSvgFile / getPngFile` | ❌ 运行时不存在 | 图像对账走截图 |

- **G-1** `net` 参数**不能传 `null`** ⇒ 传 `''`（有些接口对空串反而敏感，失败时两种都试）。
- **G-2** `create` 返回对象的 id 在 **`.primitiveId`** 属性上，不是 `getPrimitiveId()` 方法。
- **G-3** 焊盘的层信息是 `solderMaskAndPasteMaskExpansion`（**外扩量**而非层列表）
  ⇒ **焊盘模型 = 单铜层 + 派生掩膜/钢网**，表达不了"纯钢网开口"（这类开口会丢，只影响钢网层）。
- **G-4** NPTH：`create` 的 `metallization` 参要显式 `false`（前面补 `undefined`），层用 `MULTI(12)`，
  孔 `['ROUND', d]`（**只 2 个元素**）。
- **G-5** 读回字段名别猜：走线是 `net / layer / polygon / lineWidth`；焊盘编号字段是 **`padNumber`**。
- **G-6** 层号：`TOP=1 / BOTTOM=2（恒为 2）/ SILK=3,4 / MASK=5,6 / PASTE=7,8 / OUTLINE=11 / MULTI=12`；
  **内层从 15 起**（`In1=15 / In2=16`…）。⚠ `getAllLayers()` 会列出全部 Inner，**别按列表顺序推层号**。

## H. ★★★★ 铺铜（最贵的一课）

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **H1** | 板子看着没问题（走线/焊盘/覆铜框都在），**但交付的 Gerber 里一层平面都没有**（`G36/G37` 全 0） | **`Pour`（覆铜框）只是定义域，本身不画铜**；`Poured` 无 API；`Region` 不进铜；`Fill.create` 坏的 | **实心铜只有 `Fill`**：`Polyline.create(net, layer, poly, w)` → `st.convertToFill()` ✅（立刻出 `G36/G37`，`net` 被继承） |
| **H2** | 想让平面带内孔，怎么试都不行，`LPC` 恒 0 | **`Fill` 只能表达"无孔单环"** | 所有孔用**细缝（slit）**连到外边界，化成无孔多边形 |
| H3 | 拿"Copper Areas"统计判断"有没有铜" ⇒ 恒 0 | 它**只统计"覆铜对象"，不统计 `Fill` 铜** | 硬判据：**每层 `G36` 计数 == 该层落下的 `Fill` 环数**，并写进交付审计的硬断言 |
| H4 | 加了新净空但 `G36` 计数不变 | **`Fill` 无孔 ⇒ 净空靠细缝并入原环，只增顶点** | 验收看填充面积减少量 / 顶点数 / **Gerber 文件长度**，别看 `G36` |
| H5 | 用 mil 去 Gerber 里搜坐标搜不到，误判"没铜" | Gerber 坐标是 **mm（4.6 小数）** | 如 `X152400000` = 152.4mm = 6000mil |
| H6 | 表面"过孔能放下"其实放不下 | **拿铺铜净空当 DRC 间距**去卡过孔（差 1.6~2.5 倍） | **先反推本板真实 DRC 间距**，再判放置 |

## I. 导出与交付

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| I1 | `getPdfFile / getDxfFile / getIpc2581CFile` 长时间不返回 | **离线/本地模式下 Promise 永不落地** | 用**渲染图合成 PDF**，文件名带 `preview` 以示区别 |
| I2 | 拿到 `File` 却"没法直接拷到磁盘" | 返回的是**内存 `File`（无路径）** | 客户端读 `arrayBuffer` → **8KB 分块 base64** → 宿主分块拉回 |
| I3 | 坐标图按 zip 解压失败 | 它**实为 xlsx**（zip 容器） | 按真实容器类型判断，别按文件名 |
| I4 | 导出循环里"前一项秒成、下一项等很久超时" | 文件其实**已取回**，死在扩展名表 `KeyError` 被 `except` 吞掉 + 输出被缓冲 | **每项即时 flush 打印**；`except` 带 `str(e)`；写盘前 `assert key in EXT` |
| I5 | 坐标图与基线对不上，看着像放错位置 | 它有两个锚点：**几何中心**与**原点** | 比就比**原点**那一组（非对称封装会差 0.25~5.2mm） |
| I6 | Gerber 里画线指令数与走线条数对不上 | 落了实心铜之后，画线指令里会混进多边形描边 | 要么保留**加铜前的 Gerber 快照**做这一步，要么改看平面分区计数 |
| I7 | 交付审计"层齐全 + 指令数对得上"，却**整条漏掉铜平面** | 审计缺"平面"这一项 | 把 **`G36` 硬断言**写进审计脚本 |

## J. ★★★ 验收与对账（"假绿"合集）

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **J1** | 一路验收全绿，但用户说"这里不对" | **自证循环**：期望值来自我们自己的记录 ⇒ **位置类错误查不出来**（实测框线错位几厘米仍全绿） | **位置必须与外部基准量化对账**（原始 PDF 矢量 > 基准图 > 用户截图） |
| **J2** | 删失败 / 多发了一份，验收仍全绿 | 对账**只查"期望能否找到"、不查多余** | 口径必须含 **"数量对账"**；删除后**独立复核残留** |
| **J3** | DRC 打印"项数 0（通过）" | `pcb_Drc.check()` **离线恒 false**，原型上**没有"取违规结果"的入口**；写成 `Array.isArray(r)?r:[]` 会拿到空数组 = **假绿** | **DRC 不能当判据**；自己写几何验收（连通性/间隙/交付物） |
| J4 | 原理图侧 ERC 恒返固定错误、网表导出抛错或返 `undefined` | 离线模式 ERC/网表出口都是死的 | 原理图验收只走**图元层逐值 + 逐段几何对账** |
| J5 | `Text.getAll()` 条数比预期多很多 | 页框是**表格型符号**，自带一批文字 | **判页框看符号 uuid**，别用绝对计数 |
| J6 | 导线对账刷出一堆假差异 / 明明落了却报"缺失" | 平台的"连通簇编码"会产 **零长段 / 斜段 / 轴对齐连接段**；★ 而且**同一网名且端点相接的导线会被自动合并成一条**，读回可能只给其中一段 | 三条归一化：丢零长段、丢斜段、**两端都落在期望端点上的"多出段"= 连接段**（单独报数不计失败）。对**相接导线**改用"覆盖/连通"口径，别按"逐段精确匹配"（★ 实测：3 条里 2 条相接 ⇒ 稳定报 1 条缺失） |
| J7 | 连通性模型把**已连通**判成断开 | 过孔净空靠细缝相连，**盘心可能落在自己的净空腔里** | 补一条：**同层同网过孔「盘（半径 D/2）与平面环相交」也算连通** |
| J8 | 结论"某几根线一起挪就能修" | 没做**单删灵敏度** | 逐个对象单删，看"谁一让开就解锁" ⇒ 真障碍通常只有 1~2 个 |
| J9 | 假"能修" | 算障碍时**忘了把已铺的异网平面算成铜** | 平面必须计入障碍 |
| J10 | 假"重铺就能修" | 把"某层平面整片连"当成"该层是瓶颈" | 结论必须来自"**逐层点名 + 盘径全扫**" |
| J11 | 假"走线能出去" | 终点焊盘被异网铜围成小口袋 | **终点判定不限层**（终点自带的贯通过孔可从别的层扎进来）；**起点必须限在起点焊盘所在层** |
| J12 | A\* "找到"一条**直线**路径（长度 == 直线距离就是警报） | 障碍掩膜被板边禁区"先外环后内孔"整片擦掉 | **障碍掩膜与板边禁区分开画、最后合成** |

## K. 视觉与版式

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| **K1** | 自画的框线渲染成**细黑实线**（不是想要的粗蓝虚线），且肉眼很难发现 | 折线 `create(line, color?, fillColor?, lineWidth?, lineType?)` **只给坐标、其余留空 ⇒ 存成 `color=null / lineType=null / lineWidth=0.6`** | **样式参数必须显式给全**（如 `'#0000FF', 'none', 3, 1`；`1` = DASHED） |
| **K2** | 同样的图元**跨页风格不一致** | 自家封装函数把可选参数**硬编码**（如建折线工具把 `lineType` 写死 0） | **样式参数逐项透传** + 建完读回颜色/线宽/线型核对 |
| **K3** | 一排短桩线上的**网名标签互相压**（引脚间距 10 单位、标签高约 11 单位 ⇒ 必叠） | 网名写在**走线自己的 NET 属性**上 ⇒ **每条桩线都带一个标签** | ① **隐藏拥挤处的标签**（把该属性的 `valueVisible` 改 `false`，**网名仍留在走线上**）② 桩线**错开长度** ③ 把网名集中排到"标签栏" |
| K4 | "看着缺一块"但 API 读不出问题 | 渲染结果拿不到 | **图像对账**：截图反投影 + 叠色（`scripts/img_overlay.py`） |
| K5 | 同一坐标两份同名文字（字号不同），API 清不掉 | 历史遗留 + 文字不落盘 | 页源手术删除；或在生成阶段一次跑干净 |
| K6 | 元件本体压住旁边的元件 / 越过框线 | **是"摆放位置"错，还是"符号画错"？** | 用**几何投影验证**：把本体矩形 + 全部引脚外端投到基准图上；再看邻件位置 ⇒ 区分"锚点错"与"符号几何错" |
