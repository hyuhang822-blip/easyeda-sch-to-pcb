# 验收体系 · 图像对账 · 诊断方法（通用）

> 本平台最关键的方法论：**怎么证明"真的改对了"**。ERC/DRC 都不能当判据（见下），
> 验收必须自己搭，而且必须**跳出"自证循环"**。

---

## 1. ★★★★ 为什么"验收全绿"还会翻车

**对账脚本的期望值通常来自我们自己的记录** —— 这是个**闭环**：

- **位置类错误永远查不出来**：实测"整层框线错位几厘米"、"整页缺几十条框线"，**一路验收全绿**；
- **重复与缺失也查不出来**：口径若只是"期望的能不能找到"，**多余的东西不报** ——
  "以为删掉了（一百多条）其实一条没少"，验收照样全绿。

⇒ **两条硬规矩**：
1. **口径必须含"数量/条数对账"**（实测条数 vs 期望条数），不能只查"能否找到"；
2. **位置必须与外部基准量化对账**：原始矢量 PDF（最准）＞ 高分辨率基准图 ＞ 用户截图。
   **删/改之后必须独立复核残留**（读回全部图元按内容或区域再数一遍）。

## 2. 原理图侧验收（ERC 在离线模式下是死的）

**死路清单**（实测）：原理图 `Drc.check()` 恒返固定的错误项（与页数/内容/参数全无关）；
`Netlist.getNetlist()` 抛错；制造数据的网表接口返 `undefined`；`getSvgFile / getPngFile` **运行时不存在**。

⇒ **主验收 = 图元层逐值 + 逐段几何对账**：

| 项 | 判据 |
|---|---|
| 器件 | 位号集合**完全相等** |
| 电源/端口 | 网名**多重集完全相等** |
| 文字 | 每条期望文字 `(内容, x, y)` 能在画布找到（容差约 **±1 单位**） |
| 折线 | 每条期望折线几何能在画布找到 |
| 导线 | 极大段逐段对账：**缺失 / 真多出 / 网名不符 全 0** |
| NC | `器件-引脚` 集合完全相等 |
| **电气** | 逐引脚核对：总数 / 匹配数 / **断-错数** / NC 对错 / 空网 / 电源端口对错 |

★ **判页框看符号 uuid**：页框是**表格型符号**，自带一批文字，`getAll()` 会把它们算进来
（实测"自己 10 条文字读出 37 条"）⇒ **别用绝对计数**。

**导线对账的三个"必须归一化"**（否则刷一堆假差异）：
1. **零长段** —— 平台会产，直接丢；
2. **斜段** —— "一条导线所在连通簇"用**出-回游走**编码，跳段可以是斜的；
3. **轴对齐的"连接段"** —— 两端都落在期望端点上的"多出段"= 连接段（**不改连通性**，单独报数、不计失败）。

## 3. PCB 侧验收（四道独立链，缺一不可）

1. **连通性**：逐网数焊盘连通分量 + 同坐标同层异网短路。
   ★ **只有走线/焊盘/过孔/平面填充是导体**；必须做**真正的"点在多边形内"判定**（禁止包围盒近似 ⇒ 会假连通）；
   ★ 补丁：**同层同网过孔「盘（半径 D/2）与平面环相交」也算连通** ——
   否则"过孔净空靠细缝相连、盘心落在自己净空腔里"会被误判成断开（实测盘∩平面数十 mil²、
   盘心到边界不足 1 mil，物理早已连通）。
2. **铺铜间隙**：出"最小间距 vs 要求"，违规须 0 + 同网连通数不减。
3. **交付物自洽**（纯本地，不碰 EDA）：**每层平面分区计数 == 该层落下的填充环数**；
   过孔数 == 钻孔文件行数；必需层齐全；坐标图/BOM/网表计数。
   ⚠ 必须把**平面计数硬断言**写进审计，否则"层齐全 + 走线指令数对得上"会**整条漏掉铜平面**。
4. **与基线对账**：坐标图按**位号**配对拟合线性变换看残差；板尺寸/器件数/过孔数对第三方统计。
   ★ 走线指令计数只在"还没落实心铜"时等于走线条数 ⇒ 要么保留**加铜前的 Gerber 快照**，要么改看平面计数。
   ★ 坐标图有"几何中心"与"原点"两个锚点 ⇒ 比就比**原点**那一组。

## 4. ★★ 图像对账（屏幕上的东西 API 读不回来）

平台**没有导出图片/打印的 API** ⇒ 只能**用截图 + 外部基准**做量化对账。

### 4.1 定标
把截图与我们**自己画的、绝对坐标已知的图元**配对，解出 `px = s·u + b`：
- 用一个 **竖直图元** + 一个 **水平图元** 拿两个锚点；用**多个标题文字**拿尺度并交叉验证；
- ★ **横竖的 s 应相同**（等比例缩放）；不同说明配错对象；
- ⚠ 先把"**画布灰色网格**"从墨迹掩膜里排掉（用"彩色或深色"掩膜），否则定标会被网格带走
  （网格常是整十单位间距，会解出"整十整百"的假尺度）。
- ★ 用户截图一般在**剪贴板图片目录**（如 `~/.workbuddy/clipboard-images/`）——
  排查"界面看着不对"**先去找截图**。

### 4.2 反投影 + 叠色（最有效的一招）
把截图按定标映射回**页坐标**，与基准图叠色：
**红 = 基准有我们没有（缺口）/ 青 = 我们有基准没有（多余）/ 黑 = 对齐**。
一眼看出"整块缺了什么""哪里多了东西"。
⚠ 不要期望大面积黑：字体宽度、符号几何本来就不同，**红青成对出现是正常的**；
要看的是**成片的纯红 / 纯青**。

### 4.3 逐格墨迹对账（定位"整块缺失"）
把页切成格子（如 40 单位），统计每格"基准有墨迹、我们空白"，按格数排序 ⇒ 缺口集中在哪一目了然。

### 4.4 合成渲染自证
把**我们新落的图元**用绘图库画出来（文字用同尺寸字体、折线按坐标），与基准**同区域并排**
⇒ 既验证"我们画对了"，也给用户一个能看的结果。

### 4.5 几何投影验证（判"器件摆错 vs 符号画错"）
把元件的**本体矩形 + 全部引脚外端**投到基准图上：
- **本体尺寸吻合**（差 <1%）而位置差 → **摆放错**（改锚点）；
- **尺寸差很多** → **符号几何错**（改符号定义）；
- 再叠加"邻件位置对不对" ⇒ 区分"整体偏移"与"单项错位"。

### 4.6 分区域互相关（只用来找大偏差）
在若干局部窗口做互相关求最优平移。⚠ **两个陷阱**：
① **窗口太小会漏掉大偏移**（要在 ±30 之外确认没有更优）；
② **小器件/文字密集处会被噪声与符号差异污染**（实测 60/61 个器件都"报偏" ⇒ 结论不可信）。
⇒ 互相关只用于**定位大偏差**，最终判据要用"几何投影"这类**符号无关**的指标。

## 5. ★★★ 诊断"某处能不能修 / 能不能放"的五步法

0. ★★★ **先反推本板真实规则**：从现有版图用空间索引取**异网最近 edge-to-edge 距离**，
   分走线/过孔/焊盘三类给出**逐层真实最小间距**。**别猜规则**
   （拿"铺铜净空"当 DRC 间距会**把自己判进死胡同**）。
1. **盘径全扫**：目标位置逐层扫"可行盘径上限"，找出**真瓶颈层**（可行面积恒 0 的那层）。
2. **终局三问**：邻居焊盘净间距 → 盘径上限；铜岛轮廓到异网铜的距离；
   自由空间连通块里"同时摸到岛内 + 岛外同网铜"的数量（= 0 ⇒ **走线也出不去**）。
3. **给定落点 + 盘径，逐对象列"谁挡路、差多少"** —— 把"能不能放"钉成死结论。
4. **只读 what-if 平台**（最值钱的一招）：支持"临时删掉/挪动某个对象"的组合推演，
   **不碰 EDA** 就能算出"动哪几样、动多少才够"。
   - ★ **真·最大最小余量用"级别集二分解"求**（`max_p f(p) = dist(p, ∪全层障碍) − (R+clr)`），
     别用"缓冲松弛若干 mil 再取几何中点"的近似（会把近似点当全局最优，漏掉真解）；
   - ★ **凡"某几根一起挪"的结论，都要先做单删灵敏度**（逐个删，看谁一让开就解锁）——
     实测"三根并行总线"里往往只有 1 根是稻草，真障碍可能是旁边一个过孔；
   - ★ 间距审计必须**同层**比较（跨层比较会满屏假警报）+ 单独查**被挪对象互相之间**。

**三个方向不同、都会致命的坑**：
- 算障碍时**忘了把已铺的异网平面算成铜** ⇒ 假"能修"；
- 把"某层平面整片连"当成"该层是瓶颈" ⇒ 假"重铺就能修"；
- **把"整段平移"当"局部挪"**：一条长线整段抬 2 mil，会撞上几十 mil 外的其它过孔/焊盘
  ⇒ 必须做**局部折返**（两端保持原位，只平移中段，**端点不动 ⇒ 电气连通性不变**）。

## 6. 交付前自检清单（照着过一遍）

- [ ] `save()` 之后**关页签重开**再读回核对（不是只看会话内返回值）；
- [ ] **数量对账**：实测条数 == 期望条数（含"多余"这一侧）；
- [ ] **位置对账**：与外图基准量化比对（不是与自己的记录比）；
- [ ] 删除类操作：**独立复核残留 = 0**；
- [ ] PCB：连通性 / 铺铜间隙 / 平面计数断言 / 过孔数与钻孔行数 四项全过；
- [ ] 交付物：必需层齐全 + 硬断言通过 + 生成预览并**肉眼看过改动处**；
- [ ] **回滚包已生成、路径写进报告**；
- [ ] 报告落盘（含"改了什么、怎么验的、怎么退回去"）。
